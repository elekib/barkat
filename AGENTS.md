# Contributing Notes

Guide for contributors and coding agents working on Barkat.

## Rules

- Never commit `data/`, `.env` or real spreadsheets (`*.xlsx`, `*.csv`). They hold real names, balances and account details. Tests and docs use made-up sample data only.
- Money is whole cents (`Cents` in `web/src/lib/budget/types.ts`), never floats.
- Never log or return secrets.

## Build and run

- Barkat is a single Next.js app in `web/` (UI and API in one process).
- Full stack from source: `make dev` (same as `docker compose -f compose.yaml -f compose.build.yaml up --build -d`). App on port 3040 (`BARKAT_PORT`). Logs: `docker logs -f barkat`.
- Local checks in `web/`: `npm run typecheck`, `npm test`, `npm run build` (Node 22+).
- Demo data for manual testing: `npm run seed:demo` in `web/` (made-up books from 2018, in `web/data-demo/`, git-ignored). Run the app on it with `BARKAT_DATA_DIR=data-demo` and sign in as `demo` (admin) or `viewer`; the password is in the README.
- Tests live in `web/__tests__/`, mirroring `web/src/`. Import code under test with `@/` paths. Do not put tests next to source files.

## Architecture

- `web/src/lib/budget/`: the spreadsheet's logic as pure functions (`formulas.ts`) and shared types. Each formula names the original cell formula in its comment. Keep them pure so they stay easy to test against the original sheet.
- `web/src/lib/db/`: SQLite through `node:sqlite`. `openDb(file)` runs migrations; `getDb()` is the process-wide handle (`BARKAT_DATA_DIR`, default `./data`). To change the schema, append the next version to `migrations.ts`; never edit a released one.
- `web/src/lib/store/`: all reads and writes (spaces, months, rows, the new-month copy). Row columns are whitelisted per kind, so only known names reach SQL.
- `web/src/lib/budget/summary.ts`: one month's rows to the numbers shown at the top of the screen. `money.ts` parses and formats cents; `months.ts` handles `YYYY-MM`.
- `web/src/app/actions/`: server actions (`data.ts` for the books, `auth.ts`, `users.ts`). Every data action starts with `if (!(await adminOrNull())) return;`, so viewers cannot write. The hidden row-type field is `rowKind` (a bank row has its own `kind` field, so do not reuse that name).
- `web/src/lib/auth/`: Better Auth with argon2id, ported from pxls. `accounts.ts` holds the first-run setup code, users and sessions; `session.ts` has `requireUser` and `adminOrNull`; `web/src/proxy.ts` denies `/api` by default except public paths in `policy.ts`. Env names are `BARKAT_*`.
- Styling is Tailwind v3. Colours are CSS variables mapped in `tailwind.config.ts`, so utilities follow light and dark without `dark:` variants. Shared class strings live in `components/ui.ts`.
- Navigation: `components/NavBar.tsx` (top bar and mobile bottom bar) and `UserMenu.tsx`. Pages under `web/src/app/(app)/` require a session; `login/` is public.
- `node:sqlite` rows have null prototypes. Map them to plain objects before passing them to client components.
- `web/src/app/(app)/s/[spaceId]/[ym]/page.tsx`: the weekly screen. Rows are forms that `AutoForm` submits on blur or change.
- `web/src/lib/budget/accounts.ts`: pure per-account split of the cushion (`accountBreakdown`). Accounts are the month's `banks` rows; `bills`, `adhoc` and `incomes` link by `bank_id` (copy-forward remaps them, Excel and schedules match by account name, case-insensitive). Actions check an account belongs to the row's month before saving.
- `web/src/lib/budget/ledger.ts`: pure carry-forward of account balances (`carryBalances`). `loadMonth` in the store returns each account's derived `balance`, `opening`, `carried` and `made`; the `banks.balance` column is only the typed opening of an account's first month. `banks.adjust` holds an admin override of one month's balance (no entry is added); `balance + made` is the original sheet's bank figure (what `summarize` and the Excel export expect), and it is what the screens show and Manage accounts takes (`overrideBankFigure` subtracts `made` before keeping the difference); the derived `balance` stays net of Payment Made. `reconcileMonth` (import and the v5 migration) turns typed balances into openings and "Adjustment" entries.
- `web/src/lib/budget/schedules.ts`: pure payday dates for weekly, biweekly and monthly schedules. Schedules are per space (`income_schedules`); `applySchedules` in the store adds Pending income rows and skips paydays already generated (tracked by `incomes.schedule_id`).
- `web/src/lib/excel/`: workbook import and export. `layout.ts` documents the sheet layout (taken from the original sheet; extra columns L-N and Q are ours), `read.ts` parses a sheet to a month (formulas count by their last calculated value), `write.ts` builds sheets with formulas, `months.ts` reads sheet names. Export is a route handler at `s/[spaceId]/export`; import is the `importAction` server action. Tests use made-up workbooks only; never commit real spreadsheets.
- `branding/`: logo assets, all generated by `branding/generate.mjs` (see its README). Do not hand-edit the SVGs or PNGs; change the script and regenerate. `web/src/components/Logo.tsx` draws the small flat version of the mark from theme tokens.
- `web/src/lib/budget/metrics.ts` and `trend.ts`: pure numbers for the dashboard tiles and the over-time chart.
- `web/src/components/charts/`: `Charts.tsx` (ranked bars, segmented bar, meter, tile; server-rendered) and `TrendChart.tsx` (client, for the hover tooltip). Charts use the validated blue and orange series colours and the status steps; text never takes a series colour, and every chart has its values in a title, label or table view.
- Theme: colour tokens live at the top of `globals.css` (light, then dark under both the system preference and `data-theme`). `ThemeToggle` sets `data-theme`; a small script in `layout.tsx` applies the saved choice before first paint. Use the tokens, never raw hex, in components.
- `web/src/app/api/health`: health check used by the Docker image.

## Sign-off

Contributions use the DCO. Sign commits with `git commit -s`. Commits written with an AI agent also end with its `Co-Authored-By` trailer (the app is openly vibe coded under the maintainer's review; see the README).
